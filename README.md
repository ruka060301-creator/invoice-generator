# 請求書自動作成アプリ

宿泊予約管理システムからエクスポートした予約データ(CSV)を読み込み、
Excelテンプレートに流し込んで請求書を自動生成するデスクトップアプリです。

対象年月を指定するだけで、期間内の予約を抽出・集計し、請求書として出力します。

## 解決する課題

宿泊施設への送客手数料を請求する業務では、毎月以下の手作業が発生していました。

1. 予約管理システムから予約データをCSVでエクスポート
2. Excelの作業シートに40列以上を貼り付け
3. 請求書シートの明細行の数式を、その月の件数分だけ手動で伸ばす
4. 請求書番号・発行日・支払期限・手数料の名目を書き換える

手間がかかるだけでなく、次の問題がありました。

- **数式の伸ばし忘れ** — 前月より件数が増えた場合、超過分が請求額に反映されない
- **前月データの残留** — 前月より件数が減った場合、古い行が残って金額が過大になる
- **個人情報の混入** — 氏名・電話番号・住所・メールアドレスを含む全列を貼り付けていた

このアプリはこれらをすべて自動化し、構造的に防ぎます。

## 主な機能

- 予約CSVの読み込みと期間フィルタ(チェックアウト日基準)
- 1泊1行形式のデータを1予約1行に正規化
- 予約番号の重複除去(申込日が最新のレコードを採用)
- 契約開始日より前に申し込まれた予約の除外
- 件数に応じた明細行の数式の自動生成
- 請求書ヘッダー(請求書番号・発行日・支払期限)の自動更新
- 前回選択したパスの記憶

## サンプルデータで試す

実データがなくても動作を確認できるよう、架空の予約データを生成するスクリプトを同梱しています。

```bash
python generate_sample_data.py
```

`sample_data/sample_reservations.csv` が生成されます。件数や対象年月は引数で変更できます。

```bash
python generate_sample_data.py --count 130 --year 2026 --month 9
```

生成したCSVは `1予約が泊数分の行に分かれる` 形式で出力されるため、
正規化処理の動作確認にも使えます。

## 使い方

```bash
python main.py
```

1. 予約CSV・Excelテンプレート・出力先フォルダを選択する
2. 対象年月を入力する(起動時は先月が初期値)
3. 「請求書を作成」を押す

選択したパスは `settings.json` に保存され、次回起動時に復元されます。

作成されたExcelを開いたときに金額欄が空欄の場合は、`Ctrl + Alt + F9` で再計算されます。
これはopenpyxlが数式の計算結果をファイルに保存しない仕様によるものです。

## モジュール構成

| ファイル | 役割 |
|---|---|
| `config.py` | 列名・セル位置・請求ルールなどの設定値 |
| `csv_loader.py` | CSVの読み込みとフィルタ処理 |
| `excel_writer.py` | Excelテンプレートへの書き込みと保存 |
| `main.py` | tkinterによるGUI |
| `generate_sample_data.py` | 動作確認用の架空データ生成 |

### 設計方針

**データ処理とUIを分離しています。** `csv_loader.py` はExcelの構造を知らず、
`excel_writer.py` はCSVの形式を知らず、`main.py` は両者を呼び出すだけです。

この分離により、GUIをWebアプリに差し替えてもデータ処理側は無変更で動作します。
処理の各段階を個別にテストできる利点もあります。

**設定値を `config.py` に集約しています。** テンプレートのレイアウトが変わった場合も、
原則としてこのファイルのみの修正で対応できます。

## 技術的な工夫

### 1泊1行データの正規化

予約管理システムのエクスポート形式によっては、1件の予約が泊数分の行に分割されます。
このとき料金合計額には予約全体の総額が全行に入っているため、
そのまま集計すると売上が泊数倍に膨らみます。

`泊目` が1の行のみを残すことで、1予約1行に正規化しています。
もともと1予約1行の形式であれば全行が対象となるため、どちらの形式でも安全に動作します。

### 明細行の数式を毎回生成し直す

テンプレートに固定の数式を置く方式では、件数が数式の行数を超えた分が集計されません。
このアプリは明細行の数式を毎回すべて生成し直し、
件数を超えた行はクリアすることで、前回の残留も同時に防いでいます。

実データで検証したところ、テンプレートに用意されていた数式は103件分でしたが、
実際の対象月は119件でした。固定方式であれば16件が請求から漏れる状態でした。

### 個人情報を読み込まない設計

`pandas.read_csv` の `usecols` で必要な6列のみを指定しているため、
氏名・電話番号・住所・メールアドレスなどの個人情報は
そもそもメモリ上に展開されません。

「読み込んだが使わない」ではなく「読み込まない」ため、
出力ファイルへの意図しない混入が構造的に発生しません。

### 例外クラスによるエラーの一元化

`CsvLoadError` と `ExcelWriteError` を定義し、
想定されるエラーをすべてこの2つに変換しています。

GUI側は1箇所で捕捉するだけで、
「文字コードが異なる」「対象月のデータが存在しない」「ファイルがExcelで開かれている」
といった原因を日本語で表示できます。
